흐려지는 맥락

사진은 남아 있지만 장소, 날짜, 사람의 기억은 흩어짐. 앨범 속 장면과 내 기억 사이의 틈.

EDDR은 그 물음표를 “답변”이 아니라 다시 볼 수 있는 사진과 맥락으로 돌려주는 시도.

Product surface

Data insight before product

데이터 탐색이 제품 결정을 만들었습니다

Trip을 검색 단위로

사진 한 장씩 찾기보다 여행·날짜 묶음이 더 자연스러움. GPS가 있는 연속 구간으로 trip을 만들고, 같은 기간의 GPS 없는 사진도 함께 배정하는 방향.

GPS 없는 사진을 위한 UX

위치 정보가 없는 사진은 지도와 장소 필터에서 빠짐. 그래서 위치 미상 드로어, 장소검색, 날짜 그룹 일괄 지정이 제품 기능으로 필요.

Note가 검색 데이터로

캡션은 보이는 장면에는 강하지만 장소명·맥락에는 약함. 사용자가 남긴 장소와 기억을 note leg로 임베딩해 다음 검색에 합류시키는 방향.

결론: EDA의 산출물은 보고서가 아니라 M2 지도, M3 trip 기반 장소검색, M4 위치 보강, M5 메모 검색의 우선순위.

From notebook to product

노트북에서 제품 요구사항으로

결정적 인사이트는 “새 숫자 하나”가 아니라, 데이터의 빈틈이 곧 제품 기능의 형태를 정했다는 점입니다.

Decision 1 Trip 기준 확정

여행은 GPS 좌표의 연속 run과 복귀 신호로 묶고, 시간 범위가 맞는 no-GPS 사진도 trip에 편입.

Decision 2 장소검색은 메타데이터와 결합

제주·일산 같은 장소명은 캡션만으로 약함. 지역명은 trip/geocode와 OR 스코프로 합쳐 검색.

Decision 3 사용자 보강 정보가 필요

GPS가 없거나 캡션이 틀린 사진은 사람이 장소·메모를 붙이고, 그 정보가 다음 검색 품질을 올림.

데이터 범위와 빈 구간 로컬·iCloud·Google Takeout을 합쳐 제품 대상과 소스 보강 범위를 확인.
캡션 단독의 한계 장면 질의는 통과했지만 장소명 질의는 약해 trip·GPS·note 결합 필요.

Product architecture

제품 구조: 내 사진에서 지도 앱까지

1. Local data 내 사진 데이터

Photos Library, 위치 정보, 사진 설명, 사용자 메모를 로컬 SQLite와 벡터 저장소에 정리.

2. Local search 검색 서버

한국어 질문을 장소·날짜·키워드로 정리하고, 의미 검색과 메타데이터 검색을 합쳐 후보 생성.

3. Product surface 지도 중심 웹 앱

결과를 지도, 날짜 묶음, 사진 상세로 보여주고 위치 미상 사진과 메모를 다시 검색 재료로 반영.

경계: 사진 원본과 정밀 좌표는 내 Mac 안에 유지. 외부 의존은 지도 타일과 장소 검색 보조 기능으로 제한.

Demo scenario 1

첫 화면은 지도: 사진첩을 장소로 다시 보기

앱이 바로 답부터 말하지 않음사용자는 먼저 내 사진이 어디에 쌓여 있는지 지도 위에서 확인.
GPS 사진은 클러스터로 탐색많은 사진을 목록이 아니라 공간 밀도로 보여주고, 확대하면 개별 사진으로 진입.
위치 미상도 첫 화면에서 드러남지도에 못 올라가는 사진을 숨기지 않고, 보강해야 할 데이터로 노출.

Demo scenario 2

“몽골 은하수”를 검색하면 사진 lane으로 이동

한국어 질문을 검색 조건으로 정리로컬 모델은 채팅 답변이 아니라 장소·키워드·의도 해석을 담당.
결과는 날짜별 묶음여행 사진은 한 장의 정답보다 “그날의 사진 흐름”이 더 자연스러운 탐색 단위.
지도와 결과가 같이 움직임검색은 리스트를 띄우는 기능이 아니라 지도에서 기억의 위치로 이동하는 기능.

Demo scenario 3

날짜 상세에서 사진을 직접 훑어보기

긴 텍스트 답변 대신 사진 확인질문에 대한 설명보다, 사용자가 기억을 직접 복원할 수 있는 사진 탐색이 중심.
날짜와 장소 맥락 유지결과 lane에서 날짜 상세, 사진 상세로 들어가도 지도·시간 맥락이 끊기지 않음.
데모 포인트“그때 언제였지?” 같은 질문은 날짜 lane과 상세 그리드가 답을 대신함.

Demo scenario 4

위치 미상 사진은 보강 작업으로 연결

GPS 없는 사진을 별도 흐름으로 분리지도와 장소 필터에서 빠지는 사진을 날짜 그룹으로 모아 처리.
장소검색과 long-press 지정Nominatim 검색 후보나 지도 직접 지정으로 위치를 붙이고, 날짜 그룹에 일괄 적용.
EDA에서 나온 제품 결정캡션 모델만 키우는 대신, 사람이 장소를 보강하는 UX를 제품에 포함.

Demo scenario 5

메모는 사용자의 기억을 검색 데이터로 바꿈

사진에 사람이 아는 맥락을 붙임캡션이 놓친 장소명, 동행자, 사건을 사용자가 직접 남김.
저장된 메모는 임베딩되어 검색에 합류note leg가 기존 캡션 검색과 합쳐져 다음 검색 결과를 보강.
제품 루프가 닫힘찾기 어려운 사진을 발견하고, 보강하고, 다음에는 더 잘 찾는 흐름.

EDDR은 개인 사진을 로컬에서 색인하고, 한국어 질문을 지도·날짜·사진 탐색으로 바꾸는 앱. 채팅을 덜어낸 만큼 더 직접적인 UX와 privacy.

검색

운영 후보는 기본 검색 조합. 로컬 모델은 질문 정리 담당으로 유지, 키워드 부스트와 고비용 재정렬은 제외.
